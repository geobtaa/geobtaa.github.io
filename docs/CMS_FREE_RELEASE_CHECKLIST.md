## Measurement pass/fail record

Use the [network-disabled harness and safe hosted capture](CMS_FREE_QUALIFICATION.md). Record one row per API invocation: candidate/deployment SHA, UTC/time window, case tag, operation, document code units, image bytes/dimensions, active history/retry counts, module ID/first flag, HTTP/outcome, outbound count, local wall latency and available **platform** CPU quantiles for its isolated profile. Keep Node CPU in a separate field; never substitute wall time or a successful response for Cloudflare CPU.

- Cover Save Draft PUT **and its separate list refresh**, direct reopen/discovery, pending-image POST and save with uploads, PR preparation/creation/repeat/status, longer active histories, retained attempts, 32/128 KiB documents, 1/5 MiB images, and post-merge repeat editing. Use representative protected MDX as well as simple prose. Near the 100-asset/100-attempt/250,000-character bounds remains an explicit unmeasured profile, not a certified supported workload.
- Cloudflare's hard limits are 50 external subrequests and 10 ms CPU per invocation. Proposed qualification headroom: normal supported cases at most 40 calls, stress cases at most 45; available CPU upper quantiles below 10 ms, with 5 ms as a desirable headroom target. These are release criteria, not new application caps. Any observed CPU above 10 ms, resource termination or missing essential coverage prevents qualification; documented temporary CPU tolerance is not a pass.
- Capture at least 30 warm trials for supported profiles and observed module-first coverage for critical operations. Pages CPU is sampled/aggregated, not a guaranteed per-request maximum; record sampling and resolution. If dashboard aggregation cannot distinguish the profile or sufficient CPU data is unavailable, mark it **unverified**, not passed. Do not claim statistical percentiles from the two local warm samples.
- Stop the affected live write test on the first uncertain mutation/resource error. Inspect authoritative refs/PRs before retrying; keep local edits and saved drafts. Do not hammer GitHub or ignore rate-limit/Retry-After responses.
